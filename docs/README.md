# Cloud Engine — полное руководство

Версия 1.2.0.7. Единственное оформление: Classic с компактными меню.

## Установка и запуск

Запустите CloudEngine-1.2.0.7-Setup.exe, выберите язык, папку и создание ярлыка. Установка Python не требуется. Загрузчик установщика проверяет доступность временной папки и выбирает резервную при отказе доступа. Удаление через Windows сохраняет пользовательские проекты и настройки.

## Навигация

Шесть меню: Файл, Правка, Сцена, Проект, Вид, Инструменты. Добавление объектов и компонентов — Сцена; плагины и графика — Инструменты; игровые данные и проверки — Проект. Ctrl+K открывает поиск команд. Вид → Настройка интерфейса позволяет менять шрифт и видимость панелей.

## Содержание

Проекты и сцены; компоненты; ресурсы и спрайты; физика; TileMap; камера и графика; анимации и частицы; данные и поведение врагов; плагины; проверка, восстановление и экспорт. Язык описан отдельно в [Cloud Script](CLOUD_SCRIPTS.md).

# Cloud Engine


Cloud Engine — редактор 2D-игр. Движок предоставляет инструменты, а игровые
правила и механики разработчик пишет в собственных скриптах.

## Проекты и сцены

Хаб создаёт пустой проект и показывает последние открытые проекты.
Сцена содержит объекты GameObject. У каждого объекта есть обязательный Transform.
Добавляйте дочерние объекты через иерархию; их Transform задаётся относительно родителя.
Сохраняйте сцену перед выходом. При остановке Play редактор возвращается к исходной сцене.

## Нарезка спрайтов

В ресурсах дважды щёлкните по изображению или выберите «Нарезать спрайт…»
в его контекстном меню. В Sprite Studio доступны сетка с размером ячеек,
начальным отступом и зазорами и ручное выделение прямоугольных частей мышью.
Координаты и размеры выбранной части можно изменить справа. Масштаб просмотра
не влияет на пиксели исходника. Полностью прозрачные ячейки можно пропускать;
неполные ячейки на краях не экспортируются.

«Сохранить PNG…» создаёт только отдельные PNG с прозрачностью. JSON-манифест не создаётся. Части сохраняются в папку с именем исходного спрайта рядом с ним:
список ресурсов обновится, а PNG можно назначать SpriteRenderer и использовать
в качестве кадров анимации. Исходник сохраняется; существующие файлы не перезаписываются.

## Состав объекта

В инспекторе нажмите «Добавить» и найдите компонент по имени или категории.
Пустой объект не получает физику, изображение или игровое поведение автоматически.

| Компонент | Назначение |
| --- | --- |
| Transform | Положение, поворот и масштаб; нельзя удалить или выключить |
| SpriteRenderer | Текстура, цвет, отражение, кадр атласа, порядок отрисовки |
| Rigidbody2D | Масса, гравитация, сопротивление, отскок, слои столкновений |
| BoxCollider2D | Прямоугольная форма столкновений, размер и смещение |
| CircleCollider2D | Круглая форма столкновений, радиус и смещение |
| Camera2D | Область просмотра и масштаб |
| Light2D | Цвет, радиус, энергия, мягкость и тени света |
| AudioSource | Звуковой ресурс, громкость, воспроизведение через API |
| Animator | Пустой граф состояний и переходов, который настраивает разработчик |
| ScriptBehaviour | Пользовательский скрипт .cloud или .py на основе Behaviour |

Коллайдер без Rigidbody2D остаётся неподвижным препятствием. Rigidbody2D без
коллайдера движется, но не сталкивается с другими объектами. Один объект может
иметь несколько коллайдеров и несколько скриптов. Transform, SpriteRenderer,
Rigidbody2D, Camera2D, Light2D и Animator допускаются в одном экземпляре.

В меню ⋮ компонента: сброс настроек, удаление, копирование и вставка настроек,
перестановка выше/ниже. Изменения поддерживают отмену и повтор.
Собственная возможность Cloud — пресеты `.component`: сохраните настройки
компонента и загрузите их на другой объект того же типа. Пресет содержит данные,
а не код или готовую игровую механику.

Старые компоненты исключены из каталога. Для чтения уже созданных сцен оставлен
совместимый загрузчик: существующие файлы проектов автоматически не удаляются.

## Скрипты

Добавьте ScriptBehaviour и выберите ресурс из scripts/. Пример пустого скрипта:

```python
script CustomBehaviour extends Behaviour:
    export amount: float = 1.0

    on ready():
        print(self.game_object.name, self.amount)
```

Нажмите «Перезагрузить скрипты», чтобы увидеть экспортируемые поля в инспекторе.
В Python импортируйте Behaviour из engine.components.behaviour.
`self.transform` даёт Transform владельца; `self.get_component("AudioSource")`
возвращает соседний компонент. События ready, process, physics_process, input и
exit_tree вызываются для включённых скриптов. Все игровые правила пишутся здесь.
Подробности синтаксиса — в CLOUD_SCRIPTS.md.

## Ресурсы и анимация

Браузер ресурсов показывает миниатюры изображений и позволяет прослушивать звук.
Редактор атласов разрезает изображения на кадры. SpriteRenderer выбирает кадр
через hframes, vframes и frame. Для Animator создайте собственные состояния,
параметры и переходы, затем укажите AnimationPlayer с клипами через player_path.
В новом Animator нет состояний, переходов или параметров персонажа.

## Экспорт

«Собрать EXE» создаёт отдельную игру без редактора и хаба. Настройте стартовую
сцену, заголовок, размер окна и иконку. Папка экспорта должна находиться вне проекта.
У папочной сборки EXE запускается вместе с соседней папкой _internal.

## Плагины

Менеджер плагинов доступен из хаба и редактора. Поддерживает локальные ZIP-пакеты
и папки, включение, выключение и создание собственного плагина.
Встроенные плагины — инструменты редактора: проверка сцены, статистика,
резервные копии, заметки, поиск, сетка, палитра, массив объектов, атласы и снимки.
API и структура пакета описаны в README.md.


## Физика и палитра тайлов

Падающий объект: Rigidbody2D + BoxCollider2D. Пол: BoxCollider2D без Rigidbody2D.
Не перемещайте физическое тело прямой записью Transform во время симуляции:
это телепортация. Для движения используйте скорость или силу Rigidbody2D.
Проверьте размер/смещение коллайдера, enabled, freeze, слои и маски.

В палитре TileMap можно добавить отдельные PNG через «Добавить спрайты…».
Выберите тайл и включите коллизию, если он должен стать препятствием.
Флаг запоминается для каждого ID и применяется к уже нарисованным клеткам
этого тайла. Декоративные тайлы можно оставить без коллизии.

## Язык интерфейса

В хабе выберите Русский / English. В редакторе — меню «Язык / Language».
Выбор сохраняется между запусками. Названия API, компонентов и ресурсов
не переводятся. Основные панели и команды имеют английские подписи;
часть подробных сообщений и дополнительных инструментов пока остаётся русской.

## Запуск без Python

Готовый CloudEngine.exe содержит встроенный интерпретатор. Python на компьютере
пользователя для запуска редактора, Play и Cloud Scripts не нужен.
Текущая поставка — установщик и автономный EXE. Если используется собственная папочная сборка, переносите её целиком с _internal. Однофайловую сборку можно
переносить одним EXE. Пересборка исходников и экспорт новой игры используют
инструменты разработчика отдельно от запуска готовой программы.

## Плагины Cloud Engine

Менеджер доступен кнопкой «Плагины» в хабе и через меню «Плагины» в редакторе.
Встроенные инструменты включены по умолчанию. Галочка включает/отключает плагин;
в редакторе изменение применяется сразу. Настройка сохраняется между запусками.
Плагины расширяют редактор; их инструменты не включаются в экспортированную игру.

## 10 встроенных плагинов

1. Проверка сцены: отсутствующие ресурсы, повторяющиеся имена детей, стартовая сцена.
2. Статистика проекта: размер, файлы, объекты, компоненты, скрипты.
3. Резервная копия: ZIP проекта без служебных каталогов.
4. Заметки проекта: встроенный редактор PROJECT_NOTES.md.
5. Поиск объектов: поиск по имени и компоненту с фокусом на объекте.
6. Привязка к сетке: округление позиции выделенных объектов с отменой.
7. Палитра объектов: изменение цвета выделенных SpriteRenderer/спрайтов с отменой.
8. Ряд объектов: копии выделенного объекта с заданным шагом и отменой.
9. Сборщик атласов: PNG и JSON-координаты исходных изображений.
10. Снимок сцены: сохранение текущего кадра в PNG.

## Установка своего плагина

Выберите ZIP или папку с `plugin.json` и `plugin.py`. Менеджер копирует пакет
в каталог Cloud Plugins рядом с каталогом проектов. Установка не выполняет
код и оставляет новый плагин выключенным. Чтобы запустить его, поставьте галочку.
Установка поверх существующего id запрещена, чтобы не перезаписать чужой код.
Для новой версии пока используйте новый id либо замените исходники выключенного
плагина в его каталоге и снова включите его. ZIP не должен содержать выходящие
за каталог пути или символические ссылки. Ограничение: 100 МБ / 2000 файлов.

Плагины исполняют Python-код с правами редактора; это не песочница.
Устанавливайте доверенный код. Сбой загрузки отображается в менеджере и консоли.

## Создание

Кнопка «Создать свой плагин» создаёт исходники в выбранной папке.
Затем установите эту папку через менеджер. Минимальный `plugin.json`:

```json
{
  "id": "my-tools",
  "name": "Мои инструменты",
  "version": "1.0.0",
  "api_version": 1,
  "entry": "plugin.py",
  "description": "Инструменты моего проекта"
}
```

```python
def setup(context):
    def inspect_selection():
        for node in context.selected():
            context.log(node.name)
    context.add_action("Показать выделенные объекты", inspect_selection)

def teardown(context):
    # Необязательно: освободить свои ресурсы.
    pass
```

`context.editor` — главное окно. `context.project_dir` и `context.scene`
возвращают текущий проект/сцену на момент вызова, поэтому не сохраняйте их
значения навсегда при setup. `selected()` возвращает выделенные объекты.
`add_action(title, callback)` добавляет команду в меню плагинов и изолирует
ошибки её выполнения. `set_property(node, name, value)` изменяет свойство с
Undo/Redo. `refresh()` обновляет панели и помечает сцену изменённой.
`log(text)` пишет в консоль. `on_cleanup(callback)` регистрирует освобождение
своих ресурсов при отключении/перезагрузке/закрытии. Меню удаляется автоматически.
Для соседних Python-файлов используйте относительный импорт `from .helpers import ...`.

При изменении списка включённых плагинов редактор выгружает и заново загружает
все активные пакеты. Таймеры и подписки на сигналы должны освобождаться через
teardown/on_cleanup, иначе они продолжат работать после отключения.

## Проверка сцены и встроенные инструменты

Проверка перед Play теперь встроена в основное окно и не зависит от включения плагина проверки сцены. Плагин остаётся отдельным инструментом аудита проекта. Не запускайте Play из плагина в обход основного метода play_game: он выполняет предварительную проверку ресурсов, камеры и синтаксиса. Полезные API проверки: editor.scene_validation.validate_scene(scene, project_dir), возвращающий SceneIssue(node, message, path), без исполнения пользовательских скриптов.

## Cloud Engine — обновление рабочего пространства и графики

## Рабочее пространство

Меню «Рабочее пространство»: сохранить раскладку под именем, выбрать
раскладку, изменить горячие клавиши. Совпадающие назначения проверяются
при сохранении. Горячие клавиши игровых скриптов этим меню не меняются.
В сборке настройки лежат в LOCALAPPDATA/CloudEngine, а не во временной
папке распаковки EXE. Строка иерархии ищет по имени, типу и компонентам.

## Графика

Меню «Графика»: окружающий цвет, предпросмотр света и постобработки,
направляющие камеры с безопасной областью 90%, сохранение и загрузка
.postprofile для выбранного PostProcess, статистика рендера во время Play.
Профили содержат настройки, а не программный код. Окружающий цвет
сохраняется в project.json; CanvasModulate сцены имеет приоритет.

Light2D: shadow_softness и shadow_quality управляют сглаживанием края
маски тени. Это приближённое смягчение CPU-маски. Карта нормалей доступна
у SpriteRenderer. Старый нормальный проход имеет ограничения для атласов
и повёрнутых спрайтов; не считать его полноценным PBR-рендером.

Camera2D: transition_duration задаёт время перехода при смене активной камеры.
Чтобы сменить камеру, выключите предыдущую и включите следующую. Первая
включённая камера в дереве остаётся активной, если включено несколько.

Обычные последовательные Sprite2D пакетируются через pygame.Surface.blits.
Кастомная отрисовка и компоненты разрывают пакет для сохранения порядка.
Это CPU-оптимизация, не GPU-instancing. Отсечение спрайтов уже выполняется
до дорогих преобразований. render_stats показывает миллисекунды, количество
объектов и пакетов; детальные разделы доступны в профилировщике.

Загруженные ресурсы проверяются на изменение каждые 0,5 секунды.
Изменённые текстуры перечитываются, а кэши звуков и шрифтов сбрасываются.
Уже проигрываемый звук не заменяется посередине; новая версия используется
при следующем обращении к ресурсу. Удаление файла приводит к заглушке.

## Cloud Scripts

Редактор распознаёт локальные переменные вида
`body = self.get_component("Rigidbody2D")` и предлагает свойства компонента.
Меню рабочего пространства позволяет искать и переименовывать NAME-токены
в .cloud и .py скриптах. Строки и комментарии не изменяются. Это лексическая,
а не семантическая операция: разные символы с одинаковым именем тоже меняются.
Перед переименованием сохраняются копии в .cloud-backups. Динамический доступ
через строки требует ручного исправления. Просмотр переменных на точке
остановки остаётся в панели отладчика Cloud Scripts.

## Интерфейс

Компоненты HorizontalLayout и VerticalLayout размещают видимых детей
с отступом padding и промежутком spacing. auto_size рассчитывает размер
контейнера по детям. В UI Editor кнопки «Строка» и «Колонка» включают раскладку
для текущего CanvasLayer. Контейнер управляет RectTransform детей; ручное
перемещение детей такого контейнера заменяется при следующей раскладке.
Вложенные контейнеры доступны через компоненты; переноса строк и flex-весов
пока нет. Общие SVG-иконки применяются к стандартным командам окон.

## Проверка

Регрессионные тесты компонентов, физики и Cloud Scripts, проверки импорта,
пакетной отрисовки, подсказок и UI-раскладки. Наличие этих проверок не означает,
что все возможные игровые проекты протестированы.

## Палитра и запуск сцены

Палитра поддерживает фильтрацию по имени ресурса/ID, категории коллизии и избранного. Избранное сохраняется в пользовательском файле настроек; данные игровых сцен не меняются. Подробности: README.md. Предварительная проверка Play блокирует запуск при отсутствии камеры, потерянных ресурсах и ошибках компиляции .cloud/.py. Она не является полным анализатором исполнения.

## Палитра тайлов и проверка сцены

## Палитра TileMap

1. Выберите TileMap в иерархии. Назначьте атлас и число строк/столбцов либо импортируйте отдельные спрайты.
2. В поле поиска введите ID тайла или часть пути к файлу. Поиск не учитывает регистр.
3. Выберите категорию: все тайлы, с коллизией, без коллизии или избранное. Поиск работает вместе с категорией.
4. Выберите тайл и включите «★ Избранный тайл». Избранное сохраняется в пользовательском файле tile-palette.ini отдельно для проекта, имени карты и атласа. Переименование карты меняет эту привязку.
5. Зелёная рамка обозначает включённую коллизию; звезда — избранное. Синяя рамка выделяет выбранный тайл.
6. Галочка коллизии изменяет тип тайла и уже нарисованные ячейки этого типа. Изменение поддерживает Undo/Redo.

Фильтр только скрывает элементы палитры: он не удаляет тайлы из карты и не меняет выбранную кисть. Если результатов нет, очистите поиск или выберите «Все тайлы». Категории в этой версии являются фильтрами по коллизии и избранному; произвольных пользовательских тегов пока нет.

## Проверка перед Play

Перед запуском текущая сцена проверяется автоматически. При наличии ошибок Play не начинается, открывается список проблем.

- Проверяется наличие активной Camera2D с учётом системы рендера.
- Проверяются непустые свойства типа resource у объектов и компонентов, script_path и отдельные спрайты TileMap.
- Для существующих .cloud и .py выполняется проверка компиляции без исполнения кода.
- Выбор строки выделяет соответствующий объект в иерархии. Если камера отсутствует полностью, строка относится к сцене и выделять нечего.

Закройте список, исправьте проблему и нажмите Play повторно. Проверяются сохранённые файлы на диске: сначала сохраните изменения скрипта. Пустое необязательное поле ресурса не считается потерянным файлом.

## Границы проверки

Проверка синтаксиса не доказывает правильность игровых правил. Динамические импорты, исключения в ready/process, ошибки типов во время исполнения, C# и пути, собираемые в коде, требуют проверки в Play. Проверка не выполняет скрипты и не запускает внешние компиляторы.

## Запуск обновления

Из исходников: .venv2/Scripts/python.exe main.py. Для распространения требуется новая сборка через build_exe.py; ранее собранный EXE не обновляется от изменения Python-файлов проекта автоматически.

## Камера, постобработка, TileMap-компоненты и экспорт

## Постобработка

Узел PostProcess или компонент PostProcessVolume задаёт обработку всего кадра. Используйте один активный источник: система выбирает первый по порядку обхода сцены. Это глобальный эффект; пространственное смешивание нескольких объёмов пока не реализовано.

- temperature: от -1 (холоднее) до +1 (теплее), 0 не меняет цвет.
- bloom: сила свечения; bloom_threshold задаёт порог яркости.
- bloom_soft_knee: мягкость перехода порога. Малые значения дают резкое выделение ярких областей.
- bloom_radius: масштаб размытия. Свечение складывается из трёх масштабов; большие значения расширяют ореол.
- chromatic: смещение цветовых каналов с прижатием к краям кадра. Противоположные края больше не переносятся друг на друга.
- quality=fast отключает тяжёлые эффекты, включая bloom. Цветокоррекция остаётся доступной.

Это CPU-постобработка numpy/pygame, а не HDR/GPU-рендер. Настраивайте силу свечения умеренно и измеряйте время кадра.

## Камера

Camera2D доступна как узел и компонент. Новые поля автоматически доступны у обоих вариантов.

- offset: смещение центра относительно цели.
- pixel_snap: округление центра с учётом zoom для более устойчивой пиксельной графики. На дробном zoom не гарантируется целочисленный масштаб каждого спрайта.
- drag_h_enabled / drag_v_enabled: цель может двигаться внутри мёртвой зоны без сдвига центра.
- drag_left/right/top/bottom_margin: доли половины видимой области в каждом направлении.
- position_smoothing: экспоненциальное сглаживание движения; 0 — немедленное следование.
- limit_*: границы видимой области. Если мир меньше экрана, камера центрируется по границам.

## Компоненты TileMap

Выберите сам TileMap и нажмите «Добавить компонент». Компоненты сохраняются вместе с картой и редактируются в инспекторе.

- TileMapCollider2D: collision_layer и collision_mask управляют столкновениями ячеек с включённой коллизией; light_occluder — отбрасыванием тени. Выключение компонента отключает физическое тело карты. Без компонента сохраняется прежняя коллизия со слоем и маской 1. Компонент не делает декоративные ячейки твёрдыми автоматически.
- TileMapTint: color задаёт RGBA-множитель для отрисовки всех тайлов слоя. Исходные текстуры не меняются.
- PostProcessVolume: глобальные постэффекты на владельце, включая TileMap. Выключите компонент, чтобы отключить этот источник постобработки.
- ScriptBehaviour можно добавлять на TileMap для собственного поведения.

Rigidbody2D и SpriteRenderer остаются компонентами спрайтов/GameObject. Для ячеек используйте TileMapCollider2D; не добавляйте каждому тайлу отдельный Rigidbody2D.

## Экспорт Windows и macOS

В окне экспорта выберите платформу. Сборщик PyInstaller создаёт приложение только для ОС, на которой запущен.

- Windows на Windows: EXE с игровым runtime и ресурсами, без редактора.
- macOS на Mac: приложение .app в оконном режиме. При консольном режиме результат — обычный исполняемый файл/каталог.
- macOS на Windows (или Windows на Mac): ZIP с исходниками и BUILD.txt. Это пакет для последующей сборки, а не готовая игра.

Команды:

```text
python build_game.py --project path/to/project --output path/to/output --name MyGame --target windows
python3 build_game.py --project path/to/project --output path/to/output --name MyGame --target macos
python build_game.py --project path/to/project --output path/to/output --name MyGame --target macos --prepare-source
```

Распакуйте ZIP на целевой ОС, установите Python 3.13, выполните инструкции BUILD.txt. Для обычного запуска уже собранной игры Python отдельно не требуется. Дополнительные сторонние библиотеки ваших скриптов нужно установить в среду сборки отдельно. Для C# потребуются совместимые инструменты .NET.

Пакет содержит проект и runtime движка; не включайте в проект секреты или лишние файлы. Иконки: .ico для Windows, .icns для macOS. Архитектура приложения соответствует окружению сборки. Проверка на Mac, подпись и notarization выполняются отдельно; в текущей Windows-сессии сборка macOS не тестировалась.

Официальное описание ограничения PyInstaller: https://pyinstaller.org/en/stable/usage.html#supporting-multiple-operating-systems

## Автономный запуск и экспорт

## Пользовательская сборка

Откройте CloudEngine.exe из папки CloudEngine. Папку _internal нужно переносить вместе с ним. Она содержит интерпретатор, Qt, pygame, numpy, исходники инструментов, документацию и игровой player. Не нужно устанавливать Python, pip или зависимости для открытия хаба, редактирования сцен, Play и Cloud Scripts.

## Экспорт игры без Python

В установленном редакторе экспорт для текущей платформы копирует встроенный player и ресурсы проекта. В результате получается отдельная папка игры без хаба и редактора. Переносите папку целиком. Python/PyInstaller на компьютере автора и игрока для этого способа не нужны.

Доступен папочный формат. Однофайловая сборка и изменение встроенной иконки EXE требуют обычного инструментария сборки; в автономном режиме используется иконка player. Иконка окна и настройки окна берутся из проекта. Новые сторонние Python-библиотеки, не входящие в player, нужно включать в отдельную разработческую сборку; этот экспорт не устанавливает пакеты из интернета.

Если папка назначения уже существует, экспорт просит выбрать другое имя/путь и не перезаписывает её. Скрытые файлы, ссылки и служебные каталоги проекта исключаются из копирования.

## Другие платформы

Встроенный player соответствует платформе установленного редактора. На Windows он экспортирует Windows-игру. Для macOS нужен player, собранный на Mac. Выбор другой платформы создаёт ZIP исходников, для компиляции которого на целевой машине пока нужен Python с инструментами сборки. ZIP не является готовым приложением.

## Разработка самого редактора

Исходники main.py и build_exe.py по-прежнему требуют Python для внесения изменений и пересборки. Это требование разработчика движка, а не пользователя готового EXE.

## Диагностика

CloudEngine.exe --runtime-check путь/к/отчёту.json проверяет frozen runtime, создание хаба/редактора, Cloud Scripts, Play и экспорт через встроенный player без вызова внешнего python.exe.

## Cloud Engine 1.2.0-beta.1 — закрытое тестирование

## Установка

Получите один файл CloudEngine-1.2.0-beta.1.exe и запустите его из обычной папки. Python и папка _internal рядом не требуются. Runtime извлекается самим EXE во временную папку и удаляется после завершения. Поэтому запуск может быть медленнее папочной версии. Нужны свободное место во временной папке и право записи.

Проекты, экспортированные игры, резервные копии и журналы остаются отдельными пользовательскими данными. Однофайловая поставка не означает, что проект хранится внутри редактора.

## Изменения

- Физика сохраняет остаточное движение вдоль поверхности после столкновения. Отскок не разворачивает уже удаляющееся от поверхности тело.
- Play создаёт независимую копию текущей сцены в памяти. Не сохраняет сцену на диск и не меняет путь несохранённой сцены.
- Ошибка старта Play завершает частично созданную симуляцию.
- Включение/выключение компонентов запускает/останавливает их жизненный цикл. Повторное снятие не вызывает дублирующий exit.
- Проверены заливка TileMap, сохранение коллизий, выключение TileMapCollider2D и Undo/Redo.
- Контекстная команда «Переместить…» и переименование обновляют JSON-ссылки проекта. Копии изменённых файлов помещаются в .cloud-backups. История Undo сбрасывается после переноса, чтобы старые команды не вернули устаревшие пути.
- Выбор ошибки проверки сцены выделяет объект; двойной щелчок открывает скрипт. Ошибка синтаксиса в редакторе нажимается для перехода к строке. Двойной щелчок по строке traceback в консоли открывает файл проекта.

## Сценарии бета-теста

1. Создайте пустой проект, добавьте камеру, пол с BoxCollider2D и объект с Rigidbody2D/BoxCollider2D.
2. Проверьте падение, движение вдоль пола и быстрый полёт к тонкому препятствию.
3. Проверьте несколько слоёв TileMap, заливку, отмену, повтор и повторное открытие сцены.
4. Добавьте, выключите, включите и удалите компонент; сохраните и откройте сцену.
5. Запустите Play, измените объекты в игре, остановите. Редакторская сцена должна остаться исходной.
6. Переместите спрайт через браузер ресурсов. Проверьте сохранённую и открытую сцены.
7. Добавьте синтаксическую ошибку скрипта и перейдите к строке из списка.
8. Экспортируйте папочную Windows-игру и запустите её отдельно от редактора.

## Известные ограничения

Это бета, а не обещание отсутствия всех ошибок. Встроенный перенос обновляет сохранённые JSON-ресурсы и известные ссылки открытой сцены; перемещения через Проводник не отслеживаются. Пути, зашитые в текст скриптов, меняются вручную. Собственные двоичные форматы сторонних плагинов не переписываются. Не меняйте ресурсы во время Play.

Коллизии быстрых тел используют дискретные подшаги и SAT; экстремальные скорости и сложная геометрия требуют отдельного теста. Сторонние Python-пакеты не устанавливаются из интернета. Однофайловая сборка Windows не создаёт готовые macOS-бинарники на Windows.

## Сообщение об ошибке

Укажите версию, Windows/архитектуру, шаги воспроизведения, ожидаемый и полученный результат. Приложите минимальный проект без секретов и журнал startup.log. Укажите, происходит ли ошибка в Play или в экспортированной игре. До теста сделайте копию рабочего проекта.

## Исправление запуска однофайловой сборки

Runtime распаковывается в %LOCALAPPDATA%\CloudEngine\Runtime, а не в каталог из TEMP/TMP. Это устраняет зависимость запуска от недоступной системной временной папки. Путь подставляется при запуске на компьютере пользователя, а не фиксируется на машине разработчика. Отдельные каталоги _MEI создаются автоматически и очищаются загрузчиком после выхода. Для этого каталога по-прежнему нужны право записи и свободное место.

## Cloud Engine 1.2.0-beta.3

Обновление инструментов создания игры — 17 октября 2026 года.

## Редактор анимаций

Добавьте AnimationPlayer дочерним узлом персонажа или другого объекта. Выберите его в иерархии и нажмите **Редактировать анимации** в инспекторе. Пустой `root_path` означает родительский объект; при необходимости задайте путь к другой ноде сцены.

Создайте анимацию, укажите длительность и зацикливание. Во вкладке **Ключевые кадры** выберите свойство, время и значение. Повторное добавление в то же время заменяет ключ. Выбор строки возвращает её значения в поля; удаление учитывает точное время, даже если на экране оно округлено. Длительность нельзя сократить так, чтобы за её пределами остались ключи или события.

Шкала показывает синие ключи и оранжевые события. Щелчок и перетаскивание ползунка просматривают позу. **Предпросмотр** и **Пауза** работают без запуска сцены. **Вернуть объект** восстанавливает исходные свойства. Закрытие окна и «Отмена» тоже возвращают позу; «Отмена» отменяет правки клипов. Применение участвует в Undo/Redo, включая автозапуск.

Для объектов с компонентами доступны дорожки вида `SpriteRenderer.color`, `SpriteRenderer.frame`, `SpriteRenderer.texture_path`. Для атласа заранее настройте `hframes` и `vframes`, затем анимируйте `frame` со сглаживанием **Ступенькой**. **Импортировать кадры** создаёт дорожку смены текстур из выбранных файлов проекта, сортирует имена с числами естественным порядком и спрашивает частоту кадров. Эта команда заменяет дорожку текстур выбранного клипа; остальные дорожки сохраняются. Клип можно дублировать или переименовать.

## События анимации

Откройте вкладку **События**, выставьте время на шкале, введите имя, выберите тип и аргументы в виде JSON-массива, например `["stone", 1]`. Добавьте маркер. Для изменения удалите старый маркер и добавьте новый. События сохраняются внутри сцены.

**Метод** вызывает публичный метод целевой ноды или включённого компонента, в том числе экземпляра ScriptBehaviour. Получатель должен быть один; отсутствующий или неоднозначный метод сообщает об ошибке. Имена, начинающиеся с `_`, не допускаются. Аргументы передаются по порядку, без выполнения текста как кода.

Пример метода в Cloud Script, назначенном объекту через ScriptBehaviour:

```text
script PlayerEffects extends Behaviour:
    func footstep(surface):
        print("Шаг:", surface)
```

В маркере: тип «Метод», имя `footstep`, аргументы `["stone"]`. В настоящей игре тело метода может запускать AudioSource или эмиттер частиц. Само по себе имя события звук не создаёт.

**Сигнал** отправляет у AnimationPlayer сигнал `animation_event(name, args)`. Скрипт может подписаться на него через `connect`. Метод при этом не вызывается.

В Play события выполняются при пересечении маркера, включая пропущенные между кадрами и несколько циклов. Маркер в начале срабатывает один раз на запуск/цикл, в конце — перед новым циклом. Перемотка `seek()` и предпросмотр редактора событий не вызывают. Смена или остановка клипа из обработчика прерывает оставшиеся маркеры прежнего клипа. При аномально большом числе событий за один кадр выдаётся ошибка вместо зависания.

## Редактор частиц

Добавьте Particles2D и нажмите **Открыть редактор частиц** в инспекторе. Справа доступны количество, жизнь, скорость, разброс, направление, ускорение, размер в начале и конце, два цвета с прозрачностью и текстура. Слева — независимый живой предпросмотр со счётчиком частиц. Его симуляция не меняет объект сцены.

Есть заготовки **Искры**, **Огонь**, **Дым**, **Пепел**, перезапуск и пауза. Собственные настройки сохраняются в `.particles` и загружаются обратно через это окно; это файл настроек, а не отдельный запускаемый эффект. Текстуры должны быть доступны в проекте для переноса и экспорта.

**Применить** меняет настройки сцены одной отменяемой операцией, **Отмена** оставляет их прежними. Одноразовый режим теперь выпускает один пакет и завершается; для повторного запуска вызывайте `restart()`. Исправлены прозрачность, окрашивание текстур и ограничение максимального количества живых частиц. Конечный цвет и размер работают и в редакторе, и в игре.

## Автосохранение и восстановление

По умолчанию раз в 60 секунд создаётся резервная копия **всех открытых сцен данного проекта** и текста изменённого открытого скрипта. Сцены без имени файла тоже включаются. Оригинальные `.scene` и скрипты автоматическое резервирование не заменяет. Перед Play и закрытием редактора также выполняется попытка создать копию.

Меню **Восстановление** позволяет сохранить копию немедленно, открыть восстановление и задать интервал 15–3600 секунд. Копии находятся в `.cloud-recovery` внутри проекта. Сохраняются пять поколений, запись атомарная; при повреждении последнего проверяется предыдущее. Проект должен быть доступен для записи. Ошибка записи попадает в журнал, исходники остаются прежними.

При повторном открытии проекта с копией появляется выбор: восстановить, оставить до следующего раза или удалить резервные копии. «Позже» защищает найденные копии от перезаписи таймером до решения пользователя. Восстановленные сцены открываются отдельно и требуют **Сохранить как**. Скрипт восстанавливается отдельным файлом в `.cloud-recovery/restored-scripts`, чтобы случайно не загружать его второй раз из `scripts`. После проверки перенесите нужный текст в исходный скрипт.

Во время Play и модального предпросмотра копии не создаются: в них не попадут игровые изменения или временная поза анимации. При обычном закрытии копии удаляются только тогда, когда все открытые сцены и скрипт уже сохранены. Последние изменения между двумя копиями могут быть потеряны при аварии; резервирование не заменяет обычное сохранение и историю проекта.

## Понятные ошибки

В консоли появилась вкладка **Проблемы**: причина, объект при наличии контекста, файл и строка, число повторов. Ниже — пояснение, что проверить, и полные технические подробности. ## Игровые данные

Откройте **Разработка → Новые игровые данные**. Выберите категорию: оружие, враг, предмет или свои данные. В таблице задайте уникальные имена полей, типы и значения, затем сохраните файл `.gamedata` внутри проекта, например `data/sword.gamedata`. Двойной щелчок по файлу в ресурсах снова открывает этот редактор.

Типы полей: целое число, число с дробной частью, флаг, текст, вектор XY, цвет RGBA и ссылка на ресурс. Числа вводятся с точкой, флаги — `true`/`false`, вектор — `[0, 10]`, цвет — `[255, 120, 0, 255]`. Путь ресурса указывается относительно проекта; пустая ссылка допустима. Произвольный текст не выполняется как код. Повторные имена, неверные типы и нечисловые значения числовых полей не сохраняются. Запись файла атомарная.

Шаблоны лишь подставляют поля. Поле `health` само не создаёт систему здоровья, а `damage` не наносит урон: правила игры используют эти значения в ваших скриптах.

В Cloud Script доступна функция `load_data`:

```text
script Weapon extends Behaviour:
    func _ready():
        self.stats = load_data("data/sword.gamedata")

    func attack_damage():
        return self.stats["damage"]
```

Несколько объектов читают один файл. При следующем обращении запись обновляется после изменения файла; повторно копировать поля по объектам не нужно. Используйте `stats.get("damage", 1.0)` для значения по умолчанию. Полученные векторы и списки — копии, их изменение не меняет файл. Некорректное внешнее изменение файла вызывает ошибку, а не скрытое использование устаревших значений.

Для обычного Python: `GameData.load(path, project_dir)` из `engine.resources.game_data`. Также доступен `AssetManager.get_data(path)`.

Можно добавить компонент **DataSource**, назначить `data_path` и читать `self.owner.get_component("DataSource").read("damage", 1.0)` из Behaviour. Сцена хранит ссылку на файл вместо копии его полей. При перемещении ресурсов через редактор ссылки внутри `.gamedata` обновляются. Поиск неиспользуемых ресурсов учитывает эти файлы.

## Поведение врагов

1. Создайте GameObject или Sprite2D врага. Добавьте **Rigidbody2D**, подходящий коллайдер и **EnemyAI**.
2. Создайте игрока и укажите его имя или путь относительно корня сцены в `target_path`.
3. В инспекторе EnemyAI задайте скорость, дистанцию патруля, обнаружения, атаки и интервал атак.
4. Нажмите **Редактировать поведение врага**. Базовый граф содержит `patrol`, `chase`, `attack`.
5. Перемещайте карточки, меняйте действия, добавляйте состояния и связи. Положение карточек сохраняется. Применение графа поддерживает Undo/Redo; «Отмена» не меняет компонент.

Действия:

- **Ожидание** останавливает горизонтальное движение.
- **Патруль** двигается вправо и влево относительно начальной точки на расстояние `patrol_distance`.
- **Погоня** движется по горизонтали к выбранной цели.
- **Атака** останавливается и с интервалом `attack_cooldown` отправляет сигнал `attack_requested(target)`. Если задан `attack_method`, вызывается публичный метод объекта или включённого ScriptBehaviour, принимающий цель. Например `strike(self, target)` в Python или `func strike(target):` в Cloud Script. Получатель должен быть один.
- **Свой скрипт** отправляет `state_tick(state, delta)`, оставляя движение вашему коду.

Движение задаёт горизонтальную скорость Rigidbody2D, сохраняя вертикальную. Прямого перемещения через стены нет: столкновения обрабатывает физика. Выключение компонента обнуляет его горизонтальную скорость. Без физического тела движение выдаёт понятную ошибку.

Условия переходов: цель рядом, цель потеряна, цель в/вне радиуса атаки, истекло время состояния или сравнение параметра. Переходы проверяются сверху вниз; за шаг выполняется один. `*` означает любое исходное состояние. Приоритет меняется кнопками над списком. Для условия «Параметр» создайте ключ через **Параметры**, затем обновляйте его из скрипта через `ai.set_parameter("health", value)`.

`state_changed(state)` позволяет переключать анимации. Состояние атаки само не меняет здоровье и не создаёт хитбокс: это делает ваш обработчик. Обнаружение основано на расстоянии, без проверки видимости через стены; патруль не ищет путь, не перепрыгивает препятствия и не определяет край пропасти. Эти задачи остаются игровой логикой. Граф можно сохранить в `.behavior` и загрузить в другом враге; загрузка переносит копию графа, а не создаёт живую связь между файлами.

## Автоматическая проверка проектов

Сохраните сцены и скрипты. Откройте **Разработка → Автоматическая проверка проекта**, отметьте сцены и запустите проверку. По умолчанию выполняется 120 кадров симуляции на сцену, примерно две секунды игрового времени; предел одного процесса — 15 секунд реального времени. Значения настраиваются.

Сначала проверяются настройки проекта, стартовая сцена, ресурсы, синтаксис скриптов, игровые данные и графы поведения. Этот этап не исполняет пользовательские скрипты. Если есть ошибки, исправьте их и повторите запуск.

Затем для каждой сцены создаётся временная копия проекта и запускается отдельный процесс со штатными системами движка: скриптами, физикой, анимацией, частицами и отрисовкой в скрытое окно. Сцены и данные оригинала обычные операции сохранения этого процесса не заменяют. Выполняются вход в сцену, заданное число кадров и выход. Ошибки, которые компонент перехватил и записал в журнал, тоже проваливают проверку. Зависший процесс останавливается по лимиту, остальные результаты попадают в отчёт.

Кнопка **Остановить** отменяет текущую проверку. Окно остаётся отзывчивым, поскольку ожидание процессов вынесено из потока интерфейса. Отмена не считается успешным результатом.

Отчёты JSON и Markdown сохраняются в `.cloud-test-reports` внутри проекта; последний открывается из меню «Разработка». В отчёте есть результаты, ошибки и число выполненных кадров. Эта скрытая папка и резервные копии не включаются в экспорт.

В окне сборки включена галочка **Проверять сохранённые сцены перед сборкой**. После успешной проверки нажмите **Продолжить сборку**. Ошибка или отмена останавливают этот путь сборки. Галочку можно явно отключить. Прямой вызов `build_game.py` эту проверку автоматически не запускает.

Проверка запуска не доказывает отсутствие всех ошибок. Она не нажимает игровые кнопки, не проходит уровни, не проверяет баланс и не подтверждает поддержку другого компьютера. Чтобы поймать позднюю ошибку, увеличьте длительность или добавьте отдельную проверочную сцену с нужным сценарием.

## beta.6: переходы, кат-сцены, звук и командная работа

Все новые окна находятся в **Проект → Игровые данные и проверки**:
«Аудиомикшер», «Редактор кат-сцен», «Окружающий свет», «Командная работа».

### Переходы между сценами

Из Behaviour: `self.get_tree().load_scene("scenes/level2.scene")`.
Сцена загружается до выхода из прежней; переход происходит в конце кадра.
Путь должен вести к .scene внутри проекта. При ошибке загрузки текущая сцена
не выгружается. Для данных между уровнями используйте `tree.shared_data`
(словарь в памяти текущего запуска, не файл сохранения).
Play/Stop возвращает редактор к исходной сцене.

### Аудиомикшер

Master — общий уровень; Music, SFX, UI — независимые группы. Настройте уровень
0–1 и Mute, затем сохраните проект. В компоненте AudioSource выберите `bus`.
AudioStreamPlayer и AudioStreamPlayer2D тоже поддерживают эти шины.
Микшер можно открывать во время Play: уровни применяются сразу, закрытие без
сохранения возвращает прежние уровни. Музыкальные треки и эффекты загружает
сам разработчик; микшер не создаёт звуки.

API: `tree.audio_system.set_bus_volume("music", 0.5)`,
`set_bus_mute("sfx", True)`, `fade_bus("music", 0.0, 2.0)`.
Master применяется один раз. Позиционный звук сохраняет затухание от расстояния.

### Кат-сцены

Создайте дорожку: начало и длительность в секундах, относительный путь объекта,
имя компонента (или пустое поле для самой ноды), свойство и значения «От»/«До».
`.` означает корень сцены. Число: `1.5`; вектор: `[100, 200]`.
Поддерживаются position, rotation, scale, zoom, offset, energy, radius,
volume_db и color. Кривые: linear и smooth.

Пример камеры: объект `Camera`, компонент `Camera2D`, свойство `zoom`, от 1 до 2.
Для движения камеры задайте position её объекта или offset компонента.
Если камера следует за персонажем, очистите target_path для свободного движения.
Просмотр из камеры переносит редакторскую камеру в положение камеры сцены;
остановка и закрытие окна возвращают исходные свойства и вид редактора.

Сохраните ресурс .cutscene внутри проекта. Запуск из скрипта:
`self.get_tree().cutscenes.play("intro.cutscene")`.
`cutscenes.playing` позволяет отключать управление персонажем в вашем скрипте;
оно не блокируется автоматически. `cutscenes.stop(True)` останавливает и
возвращает исходные свойства. Завершённая кат-сцена оставляет финальные значения.
Это редактор дорожек свойств; монтажа видео, диалоговой системы и звуковых
событий на временной шкале в этой версии нет.

### Свет и камера

У Light2D добавлены cone_angle (360 — круговой свет, меньше — направленный конус)
и direction (градусы, 0 — вправо). Параметры доступны и на компоненте.
Тени, цвет, энергия и мягкость сохраняются в сцене. Свет за пределами экрана

Окружающий цвет настраивается через окно «Окружающий свет».

прежнее поведение. Исправлено применение offset до первого обновления камеры.
`tree.set_camera("Camera2")` включает выбранную камеру и выключает остальные;

Скрипт: scripts/templates/player_controller.cloud. Сцена: scenes/player_controller.scene.

При добавлении в существующий проект стартовая сцена не меняется. Повторное добавление получает суффикс _2, _3 и далее: существующие ресурсы не заменяются. Действия ввода имеют отдельные имена template_left, template_right, template_jump, template_run и template_restart.

Камера следует за Player с экспоненциальным сглаживанием position_smoothing=6, смотрит немного вперёд (look_ahead=65) и выше персонажа (offset=[0,-100]). После возврата на старт её сглаживание сбрасывается. Размер коллайдера персонажа — 42×90; у земли и платформ отдельные статические коллайдеры.

### Parallax2D

Добавьте Сцена → Добавить объект → Node2D → Parallax2D. Поместите Sprite2D или другие рисуемые 2D-ноды внутрь. scroll_scale задаёт долю движения камеры: [1,1] соответствует миру, [0,0] закрепляет фон относительно экрана, [0.2,0.2] создаёт дальний план. scroll_offset смещает слой, autoscroll задаёт автоматическую прокрутку в единицах в секунду. repeat_size — период повторения по каждой оси; 0 отключает повтор по этой оси. Для бесшовного фона период должен совпадать с шириной/высотой подготовленного фрагмента в мировых единицах.

Параллакс применяется только к отображению дочерних нод. Сохранённые координаты и физические коллизии не перемещаются. Не помещайте игровой пол и персонажа под декоративный параллакс. Результат виден в редакторе и игре. Старые ParallaxBackground/ParallaxLayer сохранены для совместимости.

### CanvasLayer

CanvasLayer — независимый от камеры экранный слой. offset смещает содержимое, scale масштабирует его, layer определяет порядок. Отрицательные layer рисуются за миром, нулевой и положительные — поверх мира и его постобработки. Внутри поддерживаются Label, Button, ProgressBar, TextureRect, а также Sprite2D и AnimatedSprite2D. Кнопки проверяют координаты мыши с учётом смещения и масштаба слоя. Вложенный CanvasLayer имеет собственное экранное пространство и не рисуется повторно как обычный дочерний объект. Невидимый родитель скрывает дочерние слои.

### AnimatedSprite2D

Выберите AnimatedSprite2D и откройте Инструменты → Шаблоны → Анимации AnimatedSprite2D. Создавайте именованные клипы, добавляйте PNG из проекта, меняйте порядок кадров перетаскиванием, частоту и зацикливание. Предпросмотр показывает выбранные кадры с ближайшей фильтрацией. Изменения применяются только после «Сохранить»; отмена не меняет объект. Затем сохраните сцену.

animation выбирает клип, playing включает воспроизведение, speed_scale задаёт общий множитель скорости. play("Run") меняет клип без постоянного сброса одинаковой анимации; play("Run", restart=True) начинает её заново. pause()/stop() останавливают продвижение. set_frame(i) выбирает кадр и сбрасывает его таймер. Сигналы: frame_changed, animation_looped, animation_finished (один раз при завершении незацикленного клипа). Кадры и настройки всех клипов сохраняются внутри .scene. Старые списки кадров и атласы продолжают загружаться. Проверка сцены также находит потерянные файлы кадров клипов.


## Обновление beta.8: анимация, хитбоксы, звук и кат-сцены

Общий интерфейс Classic сохранён. Три специализированных окна получили основную цветовую тему Classic и разделение на рабочую область и свойства.

### Хитбоксы по кадрам

1. Выберите ноду AnimatedSprite2D с именованным клипом.
2. Откройте «Хитбоксы по кадрам…» в меню шаблонов либо из редактора кадров.
3. Выберите кадр внизу. Тип Hit — область атаки (красная), Hurt — область уязвимости (зелёная).
4. Нарисуйте прямоугольник мышью. Перемещайте его за середину, меняйте размер за правый нижний угол либо вводите координаты справа. Координаты задаются в пикселях исходного PNG от левого верхнего угла.
5. Укажите слой уязвимости и маску атаки: это битовые маски; пересечение должно быть ненулевым. Копируйте области с предыдущего кадра или на выделенные Ctrl/Shift кадры. Ctrl+Z / Ctrl+Y отменяют и повторяют изменения в этом окне.
6. Сохраните окно, затем сцену. Отмена не меняет клип. При перестановке кадров области следуют за соответствующими PNG.

Эти области сообщают о попадании, но не заменяют BoxCollider2D, не мешают ходьбе и не снимают HP самостоятельно. Подключите hitbox_entered / hurtbox_entered в скрипте. Сохраняются внутри данных AnimatedSprite2D в сцене; отдельные JSON нарезки не создаются. Учитываются отражение, масштаб и поворот. Одна непрерывная область с одним ID поражает цель один раз; новый цикл/перезапуск клипа или исчезновение области разрешает новое попадание. Короткие кадры проверяются при обновлении анимации.

### Animator

Слева — состояния и параметры (значения JSON: число, true/false, строка в кавычках). В центре — граф Base Layer, справа — упорядоченные переходы. Блоки можно перемещать, колесо меняет масштаб, перетаскивание пустого места сдвигает граф. Начальное состояние выделено оранжевым, активное — синим. Раскладка графа сохраняется с компонентом после подтверждения и сохранения сцены. Настройка переходов остаётся в таблице справа.

### Аудиомикшер

Вертикальные фейдеры Master / Music / SFX / UI задают усиление от −80 до 0 dB; нижняя точка выключает звук. Music, SFX и UI направляются в Master. Mute отключает шину, Solo временно оставляет выбранные шины для прослушивания в Play. Solo не записывается в проект. Отмена восстанавливает состояние микшера до открытия окна, сохранение записывает громкости и Mute в project.json. Фейдеры не являются измерителями фактической громкости.

### Кат-сцены

Окно «Кат-сцены» содержит таймлайн, свойства выбранного клипа справа и вкладку расширенных табличных данных. Перетаскивайте клип для изменения начала; правый край меняет длительность. Кнопки +/− и Ctrl+колесо меняют масштаб времени. Щелчок по линейке перематывает предпросмотр. «Остановить / вернуть» восстанавливает свойства.

Типы дорожек:
- Свойство: путь объекта, необязательный компонент, свойство (например position или zoom), начальное/конечное значение и linear/smooth. Камера анимируется такой же дорожкой с путём камеры.
- Звук: существующий AudioStreamPlayer/AudioStreamPlayer2D или AudioSource, метод play, аргументы []. Плеер использует уже назначенный звуковой ресурс и останавливается по окончании длительности дорожки.
- Событие: публичный метод существующего объекта/компонента; аргументы — JSON-массив в поле «От», например [3]. Вызывается один раз при достижении времени дорожки в игровом запуске.

Предпросмотр и перемотка изменяют только свойства: события и звук выполняются при воспроизведении кат-сцены в игре. Сохраните файл кат-сцены внутри проекта и запустите через get_tree().play_cutscene(path). Старые дорожки свойств совместимы.


## Сборка для закрытого бета-тестирования: beta.9

Это тестовая сборка. Перед открытием существующего проекта сделайте его копию; проверяйте изменения в копии. Положительный результат автоматических проверок не означает отсутствия всех ошибок на других компьютерах.
